=====================================================
MISI PRODUK
=====================================================

Transformasikan Affiloom menjadi:

AI-operated affiliate product discovery, recommendation, comparison, buying-guide, and creator storefront platform.

Affiloom bukan marketplace.
Affiloom tidak menangani fulfillment.
Affiloom bukan blog AI massal.
Affiloom bukan halaman katalog link affiliate tipis.
Affiloom bukan scraper liar.

Affiloom harus membantu user menjawab:

- Produk mana yang paling cocok?
- Kenapa produk itu direkomendasikan?
- Apa kekurangannya?
- Apa alternatif yang lebih murah?
- Apa pilihan upgrade?
- Apa perbedaan produk A dan B?
- Produk mana yang cocok berdasarkan budget dan kebutuhan?
- Di merchant mana produk tersedia?
- Seberapa baru data harga dan stoknya?
- Bukti rekomendasinya berasal dari mana?

Core business loop:

USER NEED
→ DISCOVERY
→ COMPARISON
→ TRUSTED RECOMMENDATION
→ AFFILIATE CLICK
→ MEASURED OUTCOME
→ CONTENT / RECOMMENDATION IMPROVEMENT

Benchmark prinsip produk:
- Wirecutter: trust, methodology, top pick, budget pick, upgrade pick.
- PCPartPicker: utility, comparison, structured catalog, merchant offers.
- This Is Why I’m Broke: visual discovery dan shareable collections.
- The Strategist / WIRED Reviews / Gear Patrol: buying guides dan editorial commerce.
- ShopMy / creator storefront: curated collections dan creator taste.

Jangan menyalin desain, teks, database, atau intellectual property mereka.
Ambil hanya pola bisnis dan pola produk yang terbukti.

=====================================================
PRINSIP WAJIB
=====================================================

1. User utility lebih penting daripada affiliate click.
2. Tidak boleh ada fake review.
3. Tidak boleh mengaku pernah mencoba produk fisik jika tidak ada bukti.
4. Tidak boleh mengarang spesifikasi, harga, diskon, stok, rating, atau test result.
5. Semua klaim penting wajib punya provenance.
6. Affiliate disclosure wajib jelas.
7. Komisi tidak boleh memengaruhi editorial score.
8. Sponsored placement wajib dipisahkan.
9. Harga dan stok wajib punya timestamp freshness.
10. Data stale harus diberi label.
11. AI-generated summary wajib dapat ditelusuri ke sumber.
12. Tidak boleh mass-publish thin content.
13. Tidak boleh membuat doorway page.
14. Tidak boleh scraping agresif atau melanggar ToS.
15. Tidak boleh mengaktifkan biaya baru tanpa approval user.
16. Tidak boleh menghapus data production tanpa approval.
17. Tidak boleh expose secret di repo, log, issue, prompt, atau laporan.
18. Tidak boleh menyatakan selesai tanpa bukti langsung.
19. Tidak boleh melakukan rebuild total sebelum audit reuse/refactor.
20. Sistem harus tetap deployable pada setiap milestone.

=====================================================
PERINTAH MULAI
=====================================================

Mulai sekarang.

Urutan eksekusi wajib:

1. Temukan repo Affiloom lokal.
2. Buat safety snapshot.
3. Audit repository penuh.
4. Jalankan baseline test.
5. Audit `.hermes/` yang sudah ada.
6. Reuse agent/workflow existing bila layak.
7. Buat/sempurnakan multi-agent files.
8. Buat current state, gap analysis, architecture, security, backlog.
9. Claim task M0.
10. Selesaikan M0.
11. Langsung lanjut ke security fixes M1 yang reversible.
12. Jalankan test.
13. Commit.
14. Push ke remote resmi.
15. Laporkan evidence.
16. Lanjutkan milestone tanpa menunggu user, kecuali approval gate.

Jangan berhenti pada planning.
Jangan meminta repository access.
Jangan meminta user mengulang konteks.
Jangan menyuruh user melakukan terminal step yang dapat kamu lakukan sendiri.
Jangan klaim selesai tanpa live verification.
Jangan membuat biaya.
Jangan expose secret.
Jangan rebuild tanpa audit.
Jangan menyerahkan hanya template kosong.

Target akhir sesi pertama:
- audit berbasis bukti selesai;
- agent structure tersedia;
- backlog tersedia;
- security baseline diperbaiki;
- minimal satu vertical slice bernilai berhasil diimplementasikan atau diperbaiki;
- tests dijalankan;
- commit dan push dilakukan;
- status dilaporkan.
